# Zerion security claims: what is enforced, where, and since when

Every public security claim the project makes, with the code that enforces it, the test that proves it, its threat-model limits, the first version that shipped it, its current status and its external review status. Website and README wording is derived from this file; a claim that is not in this file is not made. The finer-grained protocol invariants are in [SECURITY_CLAIMS_MATRIX.md](SECURITY_CLAIMS_MATRIX.md).

Status values: **CODE-ENFORCED** (a named production invariant and a test that ran), **DESIGN GOAL** (implemented as described, no test pins it), **NOT IN 3.0.11** (being added on the `security-r1` branch, not in any release), **CODE-ENFORCED (unreleased)** (a named production invariant and a test that ran, in the source tree since the `security-r1` merge, not in any release yet). External review values: NONE, FOCUSED (an independent focused review covered it), PENDING.

## Rules for every document

- A hybrid signature's Ed25519 half equals the classical signature under the same label, so every hybrid label is distinct from every classical label; a new signature use keeps that rule.
- Marketing copy is derived from this table. "Anonymous" is not used as an absolute; "no servers" is written "no Zerion servers"; "Tor-only" is written "Tor, mandatory and always on, with the two opt-ins named".
- Historical pages keep their text and carry a dated note when they could be read as current documentation.
